# Internal Service System (ISS)

Plug-and-play mTLS-secured ingress for LAN services. One bootstrap, zero troubleshooting.

## What this is

A small system design for securing internal applications across an array of ports and domain names on a LAN. Anyone with a cert issued by the trusted CA can reach only the services they're approved for. No click-throughs. No public exposure.

## Layout

- `bootstrap.sh` — installs packages, lays down configs, starts services.
- `etc/systemd/system/*` — service units.
- `etc/traefik/*` — Traefik static + dynamic config (mTLS).
- `etc/avahi/*` — mDNS daemon config.
- `etc/step/*` — step-ca config.
- `scripts/hermes-enroll.js` — Hono node server: dark `Get connected` page. Runs on 127.0.0.1:9120.
- `templates/acl.json` — operator-maintained map of users -> allowed service hostnames.
- `.env.example` — operator secrets.

## Quickstart

```bash
git clone git@github.com:good-shepherd-insights/internal-service-system.git
cd internal-service-system
cp .env.example .env   # fill in passwords and CA host IP
sudo ./bootstrap.sh
```
